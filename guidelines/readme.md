# 공개용 README 작성 가이드

README는 프로젝트를 처음 접하는 사람이 **무엇을 하는 프로젝트인지, 어떻게 실행하고 사용할 수 있는지** 이해하도록 안내하는 문서입니다. 작업 일지나 특정 운영 환경의 관리 문서로 사용하지 않습니다.

## 기본 원칙

- 현재 기능과 사용법을 설명합니다. 변경 과정이나 작성자의 작업 상황을 서술하지 않습니다.
- 소개는 짧게, 실행법은 바로 따라 할 수 있게 작성합니다.
- 요구사항·명령어·환경 변수는 실제 설정 파일과 일치해야 합니다.
- 공개 독자가 접근할 수 있는 링크와 저장소 기준 상대 경로를 사용합니다.
- 한국어를 기본으로 하되 도구명·명령어·식별자는 원래 표기를 유지합니다.
- 별도 에이전트 지침 파일을 만들거나 작업 규칙을 README에 섞지 않습니다.

## 권장 구성

제품 소개형 구성을 기본으로 합니다. 상단에서는 프로젝트의 정체성과 실제 모습을 보여주고, 본문에서는 기능 → 설치 → 사용 순서로 안내합니다.

1. **브랜드 헤더** — 로고 또는 프로젝트명, 한 줄 소개, 핵심 배지
2. **바로가기·언어 링크** — 서비스/데모, 문서, 주요 섹션과 실제 존재하는 언어별 README
3. **대표 이미지 (선택)** — 제품 특성상 도움이 될 때 실제 화면이나 짧은 데모로 모습을 전달
4. **주요 기능** — 사용자에게 제공하는 핵심 가치를 짧은 목록으로 설명
5. **요구사항** — 런타임·패키지 관리자·필수 도구를 간결하게 정리
6. **설치·빠른 시작** — 최소 설치 명령과 첫 실행까지의 경로
7. **사용법** — 사용자가 무엇을 누르거나 어떤 명령을 실행하는지 예시로 설명
8. **개발·설정** — 개발 명령어, 필요한 환경 변수, 프로젝트 구조 등 기여자용 정보
9. **배포·참고** — 필요한 배포 방법, 상세 문서, 기여 안내, 실제 라이선스 정보

프로젝트에 필요 없는 항목은 생략합니다. 라이선스·기여 정책·지원 범위를 임의로 만들지 않습니다. 아키텍처가 필요한 프로젝트는 아래 위치 기준에 따라 개요를 추가합니다.

### 상단 구성

- 프로젝트 이름만 나열하지 말고 한 줄 소개로 무엇을 하는 제품인지 설명합니다.
- 로고가 있으면 사용하되, 로고와 큰 배너를 중복 배치해 본문을 지나치게 밀어내지 않습니다.
- 상단 브랜드 영역은 필요하면 가운데 정렬하고, 본문은 읽기 편한 기본 정렬을 유지합니다.
- 배지는 보통 3~6개 정도의 핵심 정보로 제한합니다. 기술 스택 나열보다 제품 소개와 사용 화면이 먼저 이해되어야 합니다.
- 언어별 문서는 실제 파일이 있을 때만 `한국어 · English`처럼 연결합니다. 앱의 다국어 지원만으로 번역 README가 있는 것처럼 표시하지 않습니다.
- 문서가 짧으면 간단한 섹션 바로가기를, 길면 목차를 제공합니다. 내용이 적은 프로젝트에 큰 목차를 억지로 만들지 않습니다.

### 스크린샷과 데모

- UI 앱·도구는 대표 화면 한 장을 우선 고려합니다. 소개형 홈페이지·개인 사이트는 로고, 한 줄 소개와 사이트 링크만으로 충분하면 스크린샷을 생략합니다. 이미지를 모든 프로젝트에 의무적으로 넣지 않습니다. CLI·라이브러리는 실행 예시나 짧은 출력 결과로 대체할 수 있습니다.
- 실제 구현된 화면을 사용합니다. 생성 이미지나 시안을 실제 제품 화면처럼 제시하지 않습니다. 아직 배포되지 않은 화면이면 그 상태를 명확히 표시합니다.
- 이미지에는 의미 있는 대체 텍스트를 넣고, 비밀값·계정 정보·개인 데이터가 보이지 않도록 확인합니다.
- 저장소 내 상대 경로의 압축된 이미지를 우선합니다. GIF·영상은 동작 설명에 꼭 필요할 때만 추가합니다.
- 기능별 스크린샷은 필요한 부분만 추가합니다. 비슷한 화면을 여러 장 늘어놓거나 긴 전체 페이지 캡처로 시작하지 않습니다.

### 기능과 사용법

- 기능은 구현 기술보다 사용자가 얻는 결과 중심으로 작성합니다. 보통 핵심 4~7개면 충분하며 프로젝트 규모에 맞게 조정합니다.
- 설치와 사용법을 구분합니다. 의존성 설치·개발 서버 실행만으로 사용법 설명을 대신하지 않습니다.
- 웹 서비스는 바로 접속해 사용할 수 있는 링크를 먼저 제공하고, 소스 설치는 직접 실행하려는 독자를 위해 안내합니다.
- CLI는 명령과 출력 예시, 라이브러리는 최소 코드 예시, UI 앱은 핵심 조작 흐름을 보여줍니다.
- 기술 스택·프로젝트 구조·배포 세부사항은 뒤로 두고, 긴 API·운영·개발 문서는 별도 공개 문서로 연결합니다.

### 아키텍처와 위치 기준

- 여러 서비스·클라이언트·백엔드의 관계를 알아야 실행하거나 연동할 수 있다면, README 본문에 아키텍처 개요를 둡니다. 기존 개요를 문서 축약만을 이유로 제거하지 않습니다.
- **실행 방식이나 구성 요소 선택에 필요하면 주요 기능 다음, 요구사항·설치 앞**에 배치합니다. 예: 공통 API에 CLI·TUI가 연결되고 여러 백엔드 중 하나를 선택하는 도구.
- **내부 구현 이해나 기여가 주목적이면 사용법 뒤, 개발·설정 영역**에 배치합니다. 모든 프로젝트에 같은 위치를 강제하지 않습니다.
- 그림 한 장과 짧은 역할·흐름 설명을 우선합니다. 클라이언트, 공통 서비스, 백엔드, 외부 시스템과 저장소를 필요한 범위에서 구분하고 화살표의 의미를 명확히 합니다.
- 실제 구현된 구조를 기준으로 작성합니다. 특히 앱이 소유한 데이터와 프로젝트 자체 상태 저장소, 조회와 발신 경로, 중요한 폴백 조건을 혼동하지 않도록 합니다.
- 수정 가능한 Mermaid 다이어그램을 사용할 수 있습니다. README 안에 직접 넣고, 상세 구현 문서로 연결하더라도 전체 구조는 README만으로 이해할 수 있게 유지합니다.
- 단순한 단일 프로그램은 아키텍처 섹션을 생략하거나 한두 문장으로 설명할 수 있습니다.

## 배지

- 기술 스택 배지는 실제 의존성과 지원 버전에 맞춥니다.
- 빌드·테스트 상태 배지는 실제 CI 결과를 표시하는 경우에만 사용합니다.
- 접근할 수 없는 상태 배지는 빼거나 기술/도구 배지로 대체합니다. 고정된 성공 배지로 꾸미지 않습니다.
- 배지는 핵심 정보 위주로 제한하고 라이선스 배지는 실제 라이선스 파일이 있을 때만 추가합니다.

## 공개 범위

### 포함할 내용

- 로컬 실행에 필요한 도구·명령어와 예시
- 기능 사용에 필요한 환경 변수의 이름·역할·필수 여부
- 공개 서비스 주소와 저장소 안의 파일 경로
- 범용적인 빌드·컨테이너 실행·배포 방법
- 사용자가 알아야 하는 제약과 보안상 주의사항

### 제외할 내용

- 운영용 레지스트리 주소, 내부망 IP, 개인 컴퓨터의 절대 경로
- 운영 환경에만 쓰는 인증 설정과 계정·비밀값
- 개인 인프라의 자동 업데이트 방식이나 내부 배포 절차
- 날짜별 검증 결과, 일회성 취약점 점검 보고서, 시안 변경 이력
- “이번 개편”, “이 채팅에서 확인”, “아직 커밋하지 않음” 같은 작업 상황
- 과거 이슈 번호의 나열, 임시 파일 위치, 더 이상 존재하지 않는 디렉터리

프로젝트 실행에 필요한 설정과 비밀값은 구분합니다. 필요한 변수명은 설명하되 실제 값은 공개하지 않습니다. 관련 없는 운영용 설정은 README에 나열하지 않습니다.

## 상세 문서와 작업 기록

- README에는 요약과 사용법을 두고, 긴 구현 설명은 `docs/`로 분리합니다.
- `docs/`도 공개 문서이므로 개인 경로·내부 운영 정보·로컬 작업 일지를 넣지 않습니다.
- 작업 과정과 검증 결과는 이슈·PR·CI에 남깁니다. 공개하면 안 되는 자료는 저장소 밖에서 관리합니다.
- 변경이 필요할 때 현재 내용을 고칩니다. 과거 설명에 새 설명을 계속 덧붙이지 않습니다.

## 구성 참고

- [Terminal.Gui](https://github.com/tui-cs/Terminal.Gui#readme): 대표 데모, 기능 목록, 빠른 시작과 코드 예시

- [Redoc](https://github.com/Redocly/redoc#readme): 제품 설명, 실제 화면/데모, 기능과 사용법
- [themer](https://github.com/mjswensen/themer#readme): 로고와 시각적 설명, 사용 방식별 시작 안내
- [awesome-readme-template](https://github.com/Louis3797/awesome-readme-template#readme): 브랜드 헤더·목차·소개·설치·사용법을 갖춘 범용 양식; 필요한 항목만 선택하고 예시 명령·링크·라이선스는 실제 프로젝트에 맞게 교체
- [OneBots](https://github.com/lc-cn/onebots/blob/master/README.md#架构一瞥): 소개 초반의 구성요소 역할 표와 Mermaid 아키텍처, 클라이언트·관리 서비스·어댑터·프로토콜의 경계 및 메시지 흐름 설명
