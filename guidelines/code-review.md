# 코드 리뷰

실제 변경과 요구사항을 기준으로 동작·회귀·검증 근거를 확인합니다.

## 검토 기준

- 의도한 동작과 중요한 경계 조건·실패 처리가 맞는지 확인합니다.
- 변경에 맞는 검증을 했는지 보고, 의미 없는 구현 복제 테스트나 무관한 검사를 요구하지 않습니다.
- 권한·입력 검증·비밀값·개인정보와 관련된 변경은 실제 영향 범위에서 검토합니다.
- 성능·동시성·데이터 보존에 영향을 주는 경우 관련 근거를 확인합니다.
- 코드·설정·README·API 설명이 서로 일치하는지 확인합니다.
- 프로젝트별 명시적 규칙을 우선하며 취향을 필수 수정으로 만들지 않습니다.

## 피드백

문제가 발생하는 조건, 사용자·시스템 영향, 관련 위치와 수정 방향을 구체적으로 씁니다. 확인하지 못한 가정은 사실처럼 쓰지 않습니다.

| 표기 | 의미 |
|---|---|
| `[MUST]` | 머지 전에 해결해야 하는 구체적인 문제 |
| `[SHOULD]` | 이유가 있는 개선 권고 |
| `[NIT]` | 사소한 서식·표현 제안 |
| `[QUESTION]` | 근거 확인이 필요한 질문 |

작성자는 반영 내용 또는 반영하지 않은 이유를 설명합니다. 리뷰 승인은 머지·배포 실행 요청과 별개이며 필수 리뷰 수·CI 조건은 프로젝트 정책을 따릅니다.
