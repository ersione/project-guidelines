# 릴리스 노트와 변경 이력

릴리스 노트는 한 버전에서 사용자가 알아야 할 결과와 대응을 설명합니다. 변경 이력은 같은 내용을 버전별로 누적해 찾을 수 있게 합니다. 커밋 목록이나 작업 일지를 그대로 붙이지 않습니다.

## 작성 기준

- 실제 배포 대상인 태그·커밋·이전 버전과의 변경 범위를 확인합니다. 아직 배포하지 않은 변경은 `Unreleased` 또는 초안으로 구분합니다.
- 버전과 날짜는 실제 프로젝트 정책과 배포 상태를 따릅니다. 버전 체계·출시일·배포 완료·다운로드 파일을 지어내지 않습니다.
- 추가·개선·수정 내용을 사용자 관점으로 묶습니다. 내부 구현 변경은 사용·운영·호환성에 영향을 줄 때 설명합니다.
- 호환성을 깨는 변경은 필요한 대응을 눈에 띄게 씁니다. 마이그레이션·설정 변경·복구 조건은 실제 검증 범위에서 설명합니다.
- 테스트·빌드·CI·배포 결과를 구분하고 확인한 것만 기록합니다. 제한이나 미확인 사항이 사용 판단에 중요하면 명시합니다.
- 관련 PR·이슈·비교·파일 링크는 실제 공개 가능한 대상만 넣습니다. 비밀값·개인 경로·내부 운영 정보·개인정보는 제외합니다.
- 작은 릴리스는 요약과 변경점만으로 충분합니다. 빈 카테고리와 관계없는 체크리스트는 삭제합니다.

## 릴리스 노트

[릴리스 노트 템플릿](../templates/RELEASE_NOTES.md)을 복사해 버전별 초안이나 GitHub Release 본문으로 사용합니다.

1. 한두 문장으로 이번 버전의 핵심 결과를 설명합니다.
2. 중요한 변경을 묶고 필요한 이주·설정 작업을 설명합니다.
3. 실제 검증과 남은 제한을 기록합니다.
4. 태그·배포·다운로드가 확정된 경우에만 해당 정보를 넣습니다.

릴리스 노트 초안 작성은 태그 생성·GitHub Release 게시·앱 배포 승인과 별개입니다. 이미 요청된 게시 범위가 있다면 따르고, 문서 작성만 요청된 경우에는 게시까지 추정하지 않습니다.

## 변경 이력

[변경 이력 템플릿](../templates/CHANGELOG.md)을 프로젝트 루트의 `CHANGELOG.md`로 사용합니다.

- 맨 위에 `Unreleased`, 그 아래에 최신 릴리스부터 배치합니다.
- 변경은 추가·변경·사용 중단 예정·제거·수정·보안 중 필요한 카테고리로 묶습니다.
- 배포가 확정되면 해당 변경을 실제 버전·날짜 아래로 옮깁니다. 미배포 변경은 `Unreleased`에 남깁니다.
- 과거 릴리스의 사실관계 오류는 바로잡되 새 변경을 과거 버전에 끼워 넣지 않습니다.
- 릴리스 노트와 CHANGELOG가 다른 출시 상태나 호환성 정보를 주장하지 않도록 대조합니다.

## 적용 범위

프로젝트에 릴리스·버전 관리가 필요할 때만 사용합니다. 이 템플릿 자체가 버전 증가·릴리스 생성·배포를 자동화하지는 않습니다. 자동 생성 도구를 사용하더라도 사용자 영향과 호환성 안내는 실제 변경과 대조합니다.
